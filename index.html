9.3

fhirpath: FHIRPath🔗

A FHIR resource is a small document: a patient, a lab result, a prescription. It is written as JSON, with named parts inside named parts. Sooner or later you need to point at one of those parts, or ask something about it: "the given names of the official name", "is any reading above 140". FHIRPath is the language FHIR has for that. An expression such as Patient.name.given is a path into a resource, and an expression can test what it finds: Patient.birthDate < today() - 18 years.

You meet FHIRPath all over FHIR, because the standard uses it wherever a rule has to refer to the inside of a resource: the extra rules of a profile ("a contact has a name, a phone, an address or an organization"), the definition of a search parameter, the rules of a map, the columns of a view. Where FHIR uses FHIRPath shows each.

This package evaluates FHIRPath. You give it an expression and a resource, and it gives the answer. The answer is always a list, which FHIRPath calls a collection: several values, one value, or none. An expression that names a part the resource cannot have is refused before it runs, with the name you probably meant.

Part of the fhir family of FHIR languages and tools.

1 What you can do with it🔗

  • Ask a question of one resource from the command line: A first example.

  • Try an expression out before you put it in a profile, a search parameter, a map or a view (Where FHIR uses FHIRPath).

  • Find a misspelt name. An expression is checked against the resource’s type before it runs, so Patient.nmae is an error and not a silent empty answer.

  • Compare measurements in different units: a pressure in mm[Hg] against a limit in kPa (Quantities and units).

  • Evaluate expressions from a program (From Racket).

2 A first example🔗

1. Install the tools as the family’s front page describes. The command is then raco fhirpath (or fhirpath, if you built the standalone tools).

2. Have a resource. Here is a patient with two names, an official one and the one he goes by. Save it as patient.json:

{"resourceType": "Patient", "id": "p1", "birthDate": "1974-12-25",

 "name": [{"use": "official", "family": "Chalmers", "given": ["Peter", "James"]},

          {"use": "usual", "given": ["Jim"]}]}

3. Follow a path. Give the command an expression and the file:

$ raco fhirpath "Patient.name.given" patient.json

Peter

James

Jim

Read the expression from the left. Patient says what kind of resource this is. .name goes to its names: there are two. .given goes to the given names of each of them, and the answer collects them all. Each value of the answer is printed on a line of its own.

4. Narrow it. where(…) keeps the items for which a test is true:

$ raco fhirpath "Patient.name.where(use = 'official').given" patient.json

Peter

James

Text is written in single quotes inside the expression, so put the whole expression in double quotes for the shell.

5. Ask yes or no, or how many. An expression can compare and count:

$ raco fhirpath "Patient.birthDate < today() - 18 years" patient.json

true

$ raco fhirpath "Patient.name.given.count()" patient.json

3

The first reads "was the patient born more than eighteen years before today": is this an adult.

6. Ask for something that is not there. This patient has no phone number or e-mail (telecom):

$ raco fhirpath "Patient.telecom.value" patient.json

$ raco fhirpath "Patient.telecom.exists()" patient.json

false

The first command prints nothing. That is an answer, the empty collection, and not an error: a path that leads to nothing gives nothing. When you want a yes or a no, ask with exists().

7. Make a mistake. Misspell name and the expression is refused, with the name you probably meant:

$ raco fhirpath "Patient.nmae" patient.json

<expression>: fhirpath run error: fhirpath: no element Patient.nmae (did you mean `name`?)

A patient can have no telecom, so step 6 was a fair question. No patient can have a nmae, so this one is a mistake, and it is caught before anything is read. An expression that is not well formed is reported where it stops:

$ raco fhirpath "Patient.name.given.first(" patient.json

<expression>:1:25: fhirpath parse error: the expression ends after `(`

 1 | Patient.name.given.first(

   |                         ^

3 Writing an expression🔗

This section is the language in brief, by example. The examples use the patient above and this blood-pressure reading, bp.json. It is one Observation with two components, the systolic pressure (code 8480-6) and the diastolic (8462-4):

{"resourceType": "Observation", "id": "bp", "status": "final",

 "code": {"coding": [{"system": "http://loinc.org", "code": "85354-9"}]},

 "effectiveDateTime": "2024-05-01T09:30:00Z",

 "component": [

   {"code": {"coding": [{"system": "http://loinc.org", "code": "8480-6"}]},

    "valueQuantity": {"value": 152, "unit": "mm[Hg]", "system": "http://unitsofmeasure.org", "code": "mm[Hg]"}},

   {"code": {"coding": [{"system": "http://loinc.org", "code": "8462-4"}]},

    "valueQuantity": {"value": 91, "unit": "mm[Hg]", "system": "http://unitsofmeasure.org", "code": "mm[Hg]"}}]}

The full language is described at hl7.org/fhirpath, and what FHIR adds to it at hl7.org/fhir/fhirpath.html. The repository’s guide.md has a cheat sheet, each line of it checked by the tests.

3.1 Paths🔗

A path is a chain of names separated by dots. Each name is an element: a named part of the resource, as FHIR defines it for that type.

  • Patient.name.family gives Chalmers. The type at the start is optional: name.family is the same question.

  • A step applies to every item the step before it found. That is why Patient.name.given gave the given names of both names.

  • name[0].given takes the first name only (counting starts at 0), and so does name.first().given: Peter and James.

3.2 Every answer is a collection🔗

There are no single values in FHIRPath and there is no "null". Every step takes a collection and gives a collection, and a collection with nothing in it is how the language says "not there".

This has one consequence that surprises almost everyone. The patient above has no gender:

$ raco fhirpath "Patient.gender = 'female'" patient.json

$ raco fhirpath "Patient.gender.exists()" patient.json

false

The comparison prints nothing. It is not false: the gender is unknown, so whether it equals 'female' is unknown too, and FHIRPath answers with the empty collection. A test on nothing is nothing. When that matters, say what you mean with exists() or empty(), which always answer true or false.

3.4 Text, numbers, dates and times🔗

  • Text is in single quotes: 'Peter' + ' ' + 'Chalmers' is Peter Chalmers.

  • Numbers are written plainly: (1 + 2) * 3 is 9, 10 / 4 is 2.5.

  • Dates and times start with @: @2024-05-01, @T10:30, @2024-05-01T09:30:00Z. You can add to them and compare them: @2024-05-01 + 3 days is @2024-05-04. today() and now() are the present.

  • A date may be partial, a year or a year and a month. Comparing dates of different precision has no answer: @2024 = @2024-01-01 prints nothing, because 2024 could be any day of that year. Use ~ ("equivalent") to get a plain true or false; here it gives false.

  • A day the calendar does not have is refused: @1940-02-30 is the error @1940-02-30 names no day: 1940-02 has 29 days.

3.5 Elements that can be one of several types🔗

Some elements can hold different kinds of value. An Observation’s value can be a quantity, a piece of text, a code and more. The JSON shows which by the key it uses (valueQuantity, valueString). FHIRPath calls the element by its one name, value, and you say which type you want with ofType(…):

$ raco fhirpath "Observation.component.where(code.coding.code = '8480-6').value.ofType(Quantity).value" bp.json

152

$ raco fhirpath "Observation.component.first().value.ofType(Quantity)" bp.json

{"code":"mm[Hg]","system":"http://unitsofmeasure.org","unit":"mm[Hg]","value":152}

The first asks for the number inside the systolic component’s quantity; the second for the whole quantity, which is printed as the JSON it is. Writing the JSON key is the most common mistake, and it is reported:

$ raco fhirpath "Observation.valueQuantity" bp.json

<expression>: fhirpath run error: fhirpath: direct access to choice element Observation.valueQuantity

3.6 Quantities and units🔗

A quantity is a number with a unit in single quotes: 5 'mg', 140 'mm[Hg]'. The units are spelt in UCUM, the Unified Code for Units of Measure, which is the spelling FHIR uses in data (mg, mm[Hg], kPa, mmol/L). Because the engine knows what each unit means, it converts between units of the same kind:

$ raco fhirpath "5 'mg' + 1 'g'"

1005 'mg'

$ raco fhirpath "Observation.component.where(value.ofType(Quantity) > 19 'kPa').code.coding.code" bp.json

8480-6

The second asks which components are above 19 kilopascals. The reading is in millimetres of mercury; 152 mm[Hg] is a little over 20 kPa, so the systolic component is the answer.

Units of different kinds cannot be compared or added. 1 'kg' > 3 'cm' prints nothing (there is no answer), and 1 'kg' + 3 'cm' is the error incompatible quantity units.

Spans of time are written without quotes: 18 years, 3 days.

3.7 Names that start with %🔗

A name that starts with % is a value given from outside the expression. Some come built in:

  • %resource is the resource the expression started from, wherever in it you are now.

  • %loinc, %sct and %ucum are the addresses of three code systems, so Observation.component.code.coding.where(system = %loinc).code gives 8480-6 and 8462-4.

  • A program can pass its own (From Racket).

4 Where FHIR uses FHIRPath🔗

You rarely write FHIRPath for its own sake. You write it inside something else, and the command line is the place to try it out first.

  • Invariants in profiles. A profile says what a valid resource looks like, and an invariant is a rule in it that the simple checks ("this element is required") cannot express. FHIR’s own rule that an Observation has a value or a reason why not, but never both, is the invariant dataAbsentReason.empty() or value.empty(). An invariant holds when it answers true:

    $ raco fhirpath "dataAbsentReason.empty() or value.empty()" bp.json

    true

    In FHIR Shorthand you write one as an Invariant: with an Expression: (fsh), and the family’s validator evaluates it with this engine.

  • Search parameters. A search such as Patient?given=Peter works because FHIR defines the parameter given for patients as the expression Patient.name.given: a server evaluates it over each stored resource and indexes what comes out. A parameter that serves several types is written with a bar between them (Patient.name.given | Practitioner.name.given); try the part for your resource’s type.

  • Mapping rules. In the FHIR Mapping Language the condition of a rule is FHIRPath: src.item as item where (linkId = 'gender') (fml).

  • View columns. A SQL on FHIR view turns resources into a table, and each column is a FHIRPath expression over the resource: a column with the path name.family.first() holds Chalmers for the patient above (sql-on-fhir).

  • Clinical logic. CQL, the language for clinical rules and quality measures, builds on FHIRPath’s expressions (cql).

Within this family there is one FHIRPath engine, this one. The validator, the server’s search, the mapping language, FHIR Shorthand’s checks and the views all use it, so an expression means the same thing wherever you put it.

5 Running it🔗

5.1 Command line🔗

The command evaluates one expression over one resource.

raco fhirpath '<expr>' resource.json

  

the answer, one value per line; the resource is read as FHIR R5

raco fhirpath '<expr>' resource.json --r4

  

the same, the resource read as FHIR R4

raco fhirpath '<expr>'

  

no resource: the expression runs over the empty collection, which is enough for arithmetic

raco fhirpath --tck [r5|r4]

  

run HL7's FHIRPath test suite (r5 when not said)

raco fhirpath --ucum-tck [-v]

  

run UCUM's functional tests

How a value is printed: text as itself; a number, a date, a quantity or true/false the way FHIRPath writes it (152, @1974-12-25, 5 'mg', true); an item that has parts of its own (a name, a quantity taken from a resource) as its FHIR JSON on one line. An empty answer prints nothing.

Use --r4 for data written to FHIR R4 (version 4.0.1), which is what US Core and the International Patient Summary use. The versions differ in which elements a type has, so the check for misspelt names depends on it.

An error is reported as text by default. --format json writes it as JSON and --format outcome as a FHIR OperationOutcome, for a program to read. The command exits with 0 when all is well, 1 on a FHIRPath error (or when a test suite does worse than before), and 2 when it was called wrongly or cannot read the file.

5.2 From Racket🔗

From a program you do three things: read the resource, read the expression, evaluate. The resource must be read as a typed value, one that knows it is a Patient and what a Patient has, so load the definitions of a FHIR version first (fhir/r5/schemas, fhir/r4/schemas or fhir/r6/types).

(require fhir/r5/schemas fhir/serialize/from-json fhir/serialize/read-json fhir/result/result
         fhirpath/parser/parse fhirpath/eval fhirpath/value)
(define patient
  (ok-value (from-json (call-with-input-file "patient.json" read-fhir-json) #:lenient? #t)))
(define given (eval-fhirpath (parse-fhirpath "Patient.name.given") (list patient)))
(map item->system given)                                       ; '("Peter" "James" "Jim")
(eval-fhirpath (parse-fhirpath "birthDate < @1980") (list patient))   ; '(#t)
(eval-fhirpath (parse-fhirpath "Patient.telecom") (list patient))     ; '()

Every result is a collection, a Racket list; the empty collection is '(). An item is a typed node (navigate on from it, or turn it into JSON with node->jsexpr), a FHIR primitive, or a plain value (Values). item->system turns a FHIR primitive into its plain value, and item->text (fhirpath/render) prints any item the way the command line does. parse-fhirpath remembers what it has parsed, so parsing inside a loop costs nothing after the first time.

There is no #lang for FHIRPath: an expression is a string you evaluate, not a module.

  • Your own % names are passed by name without the %, each as a collection: with #:externals (hash "limit" '(2)), the expression name.given.count() > %limit answers '(#t) for the patient above.

  • Terminology. The external "terminologies" may hold a tx-service from the fhir-tx package, as (list tx). That makes %terminologies.expand(…), validateVS(…) and translate(…) work: the expression can ask whether a code is in a value set.

  • The check before running. With one typed node as input, eval-fhirpath first runs analyze. An element the type does not have, or a choice element read by its JSON key (Observation.valueQuantity), raises a 'semantic error before anything is evaluated. #:strict? #f allows the JSON key, as the specification’s lenient mode does; a name the type does not have is still an error.

  • Errors. A syntax error raises exn:fail:diagnostic (fhir/diagnostic) with the position. An evaluation error raises exn:fp (fhirpath/error), whose exn:fp-kind is 'syntax, 'semantic or 'execution: for example 'semantic for Patient.nmae, and 'execution for name.given.single() when there are three.

6 In an editor, and for an AI agent🔗

  • In an editor. The family’s language server, fhir-lsp, treats a .fhirpath file as one expression and underlines a syntax error where it is. It loads fhirpath/support for this.

  • For an agent. In an fhir-mcp workspace an expression runs over every resource of a type at once (Patient.name.given reads every Patient), and explain gives the value of each part of the expression for one resource, so you can see the step where a value disappears. This is fhirpath/workspace. The repository’s guide.md is the language written for an agent to read (fhir-mcp serves it as learn://fhirpath), and .claude/skills/fhirpath is the same workflow for an agent using the command line.

7 Limits🔗

  • One expression, one resource. The command line evaluates a single expression over a single resource, as FHIR R4 or R5. To ask the same question of many resources, use a workspace or a program; from a program FHIR R6 works too.

  • Following references. resolve() follows a #id reference into the resource’s own contained resources only. It does not fetch another resource.

  • Profiles. conformsTo(url) checks that the resource is of the base type the url names, not that it meets a profile’s rules. Use the validator for that.

  • Tracing. trace() passes its input through and logs nothing.

  • Terminology. %terminologies has expand(), validateVS() and translate(); it does not have lookup(), validateCS(), subsumes() or memberOf().

  • Newer functions. These additions of FHIRPath 3.0 are not implemented: lastIndexOf, coalesce, sum, min, max, avg, toLong, the yearOf … millisecondOf components, dateOf, timeOf, duration, difference, repeatAll. Using one is the error unknown function sum().

  • The check before running is cautious. It stops as soon as it no longer knows the type it is looking at (after resolve(), a step that can be several types, or a function it does not model). So it never refuses a valid expression of that kind, and it does not catch every mistake.

  • A path through another type is refused: over a Patient, Patient.name.given | Practitioner.name.given is the error no element Patient.Practitioner. Evaluate the part for the resource’s own type.

  • Two cases of HL7’s R4 suite fail on purpose. Adding a fraction of a second to a time (@T… + 0.1 's'): R4 drops the fraction and R5 keeps it, and the engine follows R5. And (-0.0034).lowBoundary(1) is expected to be -0.0; decimals here have no negative zero.

8 Words used here🔗

  • Resource: one FHIR document, such as a Patient or an Observation, written as JSON.

  • Element: a named part of a resource, as FHIR defines it for the resource’s type (name, birthDate).

  • Expression: a piece of FHIRPath; what you give the command. A path is the simplest kind: element names joined by dots.

  • Collection: a list of values. Every FHIRPath answer is one. The empty collection is how FHIRPath says "nothing there"; it is written {}.

  • Choice element: an element that can hold one of several types, such as an Observation’s value. In JSON it is valueQuantity or valueString; in FHIRPath it is value.ofType(Quantity).

  • Profile: a set of rules a resource must follow in some setting, on top of FHIR’s own. An invariant is one such rule written as a FHIRPath expression that must answer true.

  • Search parameter: a name a FHIR server lets you search by (given, birthdate), defined by the FHIRPath expression that finds its values.

  • Quantity: a number with a unit. UCUM: the Unified Code for Units of Measure, the standard spelling of units (mg, mm[Hg]) that FHIR uses.

  • Code system: where codes come from, such as LOINC or SNOMED CT. A value set is a named set of codes; a terminology service answers questions about them.

  • System types: FHIRPath’s own plain values: Boolean, Integer, Long, Decimal, String, Date, DateTime, Time, Quantity. A FHIR primitive (a FHIR date, a FHIR code) wraps one of them.

  • Strict mode: the check of an expression against the resource’s type before it runs.

  • External: a value passed to an expression under a % name.

  • Typed node, tower: for programmers. A resource read into a value that knows its FHIR type is a typed node; the definitions of one FHIR version’s types (R4, R5, R6) are a tower.

9 How it is tested🔗

Against the suites HL7 and UCUM publish, kept in the repository as published:

  • HL7’s FHIRPath suite for R5: all 1044 tests pass. For R4: 932 of 934; the two that do not are described under Limits.

  • UCUM’s functional tests (validity, display names, conversion, arithmetic on units): all 573.

  • Every expression in the repository’s guide.md is parsed and its worked examples are replayed through the command line, so what it shows is what you get.

raco fhirpath --tck r5, raco fhirpath --tck r4 and raco fhirpath --ucum-tck run the suites; each fails if the count drops below what it was. raco test . in the repository runs the unit tests that every module carries. The repository’s TESTING.md has the table.

For programmers: the modules of the package and what each provides.

fhirpath/parser/parse🔗

One expression to its AST (immutable prefab structs). An empty string or a program of several expressions is an error.

  str : string?
A ;-separated program to a list of ASTs. A syntax error raises exn:fail:diagnostic with the position, and "the expression ends after (" when the input ran out.

fhirpath/analyze🔗

 (require fhirpath/analyze) package: fhirpath

procedure

(analyze ast root-type [#:strict? strict?]) → void?

  ast : any/c
  root-type : (or/c symbol? #f)
  strict? : boolean? = #t
The static pass: raises a 'semantic error for an element the type does not have (with the nearest name), a string function applied to a complex type, an order-dependent function on an unordered source, and in strict mode an expanded choice access. It looks inside both operands of an operator and inside function arguments such as where’s. It stops wherever the type becomes unknown, so it never rejects a valid expression it cannot fully type.

fhirpath/print🔗

 (require fhirpath/print) package: fhirpath

procedure

(fhirpath->string ast) → string?

  ast : any/c
