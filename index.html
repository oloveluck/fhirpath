fhirpath: FHIRPath for Racket🔗

A FHIRPath engine over typed FHIR resources: parser, evaluator, the System types (precision-aware decimals, partial dates and times, quantities with a full UCUM engine) and a static check for strict mode. It is a library, not a #lang: the cql, fml and fsh packages embed it, and the validator evaluates invariants and search parameters with it. It passes the official HL7 suites (R5 1044 of 1044, R4 932 of 934) and the UCUM functional tests (573 of 573). Part of the fhir family.

1 Quick start🔗

1. Install. The packages are not on the Racket package server yet; clone the repositories side by side and install from source:

raco pkg install --link --auto fhir/fhir fhirpath

2. Evaluate an expression over a resource.

$ raco fhirpath 'Patient.name.given' patient.json

Peter

James

$ raco fhirpath 'birthDate < @1980' patient.json

true

$ raco fhirpath '(1 + 2) * 3'

9

Primitives print as text, complex items as FHIR JSON. R5 by default, --r4 for R4. A syntax error is positioned: <expression>:1:14: fhirpath parse error: the expression ends after ‘(‘.

2 Using it🔗

2.1 From Racket🔗

Expressions evaluate over typed nodes, so load a version tower first (fhir/r5/schemas, fhir/r4/schemas or fhir/r6/types); then parse the resource, parse the expression, evaluate.

(require fhir/r5/schemas fhir/serialize/from-json fhir/serialize/read-json fhir/result/result
         fhirpath/parser/parse fhirpath/eval fhirpath/value)
(define patient
  (ok-value (from-json (call-with-input-file "patient.json" read-fhir-json) #:lenient? #t)))
(define given (eval-fhirpath (parse-fhirpath "Patient.name.given") (list patient)))
(map item->system given)                                       ; '("Peter" "James")
(eval-fhirpath (parse-fhirpath "birthDate < @1980") (list patient))   ; '(#t)

Every result is a collection, a Racket list; an empty collection is '(). Items are typed nodes (navigate on, or node->jsexpr them), FHIR primitives, or System values (Values); item->system collapses a primitive to its System value. parse-fhirpath is memoized, so parsing inside a loop costs nothing after the first time.

  • Externals are passed by name without the %: #:externals (hash "ucum" '("http://unitsofmeasure.org")). "terminologies" may hold a tx-service from fhir-tx, as (list tx), which makes %terminologies.expand() and friends work.

  • Strict mode. With one typed node as input, eval-fhirpath first runs analyze: an element the type does not have, or a direct expanded-choice access (Observation.valueQuantity), raises a 'semantic error before anything runs. #:strict? #f allows the choice access, as the spec’s lenient mode does.

  • Errors. A syntax error raises exn:fail:diagnostic (fhir/diagnostic) with the position; an evaluation error raises exn:fp whose kind is 'syntax, 'semantic or 'execution.

2.2 Command line🔗

raco fhirpath ’<expr>’ resource.json

  

one result per line (R5; --r4 for R4)

raco fhirpath ’<expr>’

  

no resource: over the empty collection

raco fhirpath –tck [r5|r4]

  

the HL7 FHIRPath suite, floor-ratcheted

raco fhirpath –ucum-tck [-v]

  

the UCUM functional tests

--format text|json|outcome chooses how an error is reported. Exit codes: 0, 1 on a FHIRPath error or a suite regression, 2 on usage.

3 In an editor, for an agent🔗

fhirpath/support is what the family’s language server (fhir-lsp) and MCP server (fhir-mcp) load for FHIRPath: a document’s diagnostics (one expression; a syntax error positioned) and the tool fhirpath_evaluate. It is a fhir/lang/support value.

4 Limits🔗

  • Two R4 suite cases fail by design: fractional seconds in @T…+0.1 ’s’ (R4 truncates, R5 keeps them; the engine follows R5) and (-0.0034).lowBoundary(1) = -0.0 (decimals have no signed zero).

  • resolve() follows #id references into the root’s contained resources only. conformsTo(url) checks the base type the url names, not a profile’s constraints. trace() passes through without logging.

  • %terminologies has expand(), validateVS() and translate(); not lookup(), validateCS(), subsumes() or memberOf().

  • Not implemented from FHIRPath 3.0: lastIndexOf, coalesce, sum, min, max, avg, toLong, the yearOf … millisecondOf components, dateOf, timeOf, duration, difference, repeatAll. An unknown function is a 'semantic error.

  • Strict mode is conservative: it stops once a type is unknown (after resolve(), a polymorphic step, or a function it does not model), so it never rejects a valid expression and does not catch everything.

5 Reference🔗

fhirpath/parser/parse🔗

 (require fhirpath/parser/parse) package: fhirpath

procedure

(parse-fhirpath str) → any/c

  str : string?
One expression to its AST (immutable prefab structs). An empty string or a program of several expressions is an error.

procedure

(parse-fhirpath-program str) → list?

  str : string?
A ;-separated program to a list of ASTs. A syntax error raises exn:fail:diagnostic with the position, and "the expression ends after (" when the input ran out.

fhirpath/eval🔗

 (require fhirpath/eval) package: fhirpath

procedure

(eval-fhirpath ast    
  root    
  [#:externals externals    
  #:strict? strict?]) → list?

  root : list?
  externals : hash? = (hash)
  strict? : boolean? = #t
Evaluates ast with root as the input collection and returns the result collection. When root is a single typed node, analyze checks the expression against its type first.

procedure

(fp-eval ast focus env) → list?

  ast : any/c
  focus : list?
  env : env?
The evaluator proper: ast over the focus collection in an environment built with make-env.

fhirpath/analyze🔗

 (require fhirpath/analyze) package: fhirpath

procedure

(analyze ast root-type [#:strict? strict?]) → void?

  ast : any/c
  root-type : (or/c symbol? #f)
  strict? : boolean? = #t
The static pass: raises a 'semantic error for an element the type does not have, a string function applied to a complex type, an order-dependent function on an unordered source, and in strict mode an expanded choice access. It stops wherever the type becomes unknown, so it never rejects a valid expression it cannot fully type.

fhirpath/print🔗

 (require fhirpath/print) package: fhirpath

procedure

(fhirpath->string ast) → string?

  ast : any/c
The AST back as text, every nested binary operation parenthesized: (fhirpath->string (parse-fhirpath "a and b or c")) is "(a and b) or c". Printing then parsing is a fixpoint.
